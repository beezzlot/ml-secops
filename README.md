# Приоритизация окон аутентификации для SOC

Учебный проект: сравнение Logistic Regression, Random Forest и Isolation Forest для формирования очереди расследований при бюджете восемь окон в сутки UTC.

Данные полностью синтетические. Одна строка описывает одну учётную запись в закрытом 15-минутном окне. Метка `target=1` означает, что окно требует расследования по сценарию генератора.

## Состав проекта

- `soc_auth_queue_homework.ipynb` — код, проверки данных, результаты и выводы.
- `requirements.txt` — версии зависимостей.
- `frozen_config.json` — конфигурация решения, выбранного по valid перед итоговой проверкой на test.

Генератор находится внутри notebook, скачивать данные отдельно не нужно.

## Запуск

Окружение: Python 3.12. Проверка выполнена на Python 3.12.10.

Команды для Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install -r requirements.txt
python -m pip install jupyterlab ipykernel
python -m jupyter lab
```

Откройте notebook, выберите ядро из `.venv`, перезапустите его и выполните все ячейки сверху вниз. Затем сохраните notebook с результатами.

## Протокол проверки

- Train: 1–14 января 2026 года.
- Valid: 16–20 января.
- Test: 22–26 января.
- 15 и 21 января исключены для учёта задержки меток на 24 часа.

Преобразования и модели обучаются только на train. Настройки и итоговый метод выбираются по valid. Test используется для проверки зафиксированного решения без дообучения.

Очередь формируется отдельно за каждые сутки UTC: оценка по убыванию, при равенстве — `row_id` по возрастанию, затем первые восемь окон.

## Результаты

На valid — 9 600 окон, из них 106 положительных. Каждый метод выбирает 40 окон за пять суток.

| Метод | TP | FP | precision@8 | recall@8 |
|---|---:|---:|---:|---:|
| Logistic Regression | 23 | 17 | 0,575 | 0,217 |
| Random Forest | 33 | 7 | 0,825 | 0,311 |
| Isolation Forest | 13 | 27 | 0,325 | 0,123 |

По valid выбран Random Forest: 200 деревьев, `min_samples_leaf=50`, `max_depth=None`, `random_state=42`.

На test при том же ежедневном top-8: 32 TP и 8 FP, precision@8 — 0,800, recall@8 — 0,302. Дневной бюджет соблюдён.

## Ограничения

Очередь строится после окончания суток и не моделирует немедленную реакцию. Проверяется будущая активность тех же учётных записей, а не новых пользователей. Результаты характеризуют синтетический генератор и не подтверждают готовность к реальному внедрению или автоматическим блокировкам.

Описание использования ИИ и выполненных проверок приведено в notebook.
